# 流程与数据工作台

在同一个本地 Web 应用中梳理**业务如何运行**，以及**系统和数据如何支撑它**。每条业务流程独立保存，通过共享资产关联已有系统、数据库、表、接口、文件和外部方；原有数据流采集、人工维护和三视图能力继续保留。

## 快速体验

启动后打开 [http://localhost:5173](http://localhost:5173)，点击 **新建流程 → 申请审批示例 → 创建流程图**。示例包含提交、审核、判断、执行和退回修改，可直接拖动节点、编辑属性或关联已有资产。通过顶部 **图目录** 在多张流程与 **数据关系总图** 之间切换。

完整操作与备份说明见 [流程图使用指南](docs/process-guide.md)。

## 功能

- **多流程文档**：独立命名、说明、节点、连线和排版；支持新建空白流程、审批示例、编辑流程信息和删除指定流程。删除流程保留共享资产。
- **基础流程图**：开始、处理步骤、条件判断、结束四种节点；点击或拖入画布，拖动圆点创建有向连线。判断提供“是 / 否”出口，连线可填写条件说明，支持退回环路。
- **步骤属性**：名称、负责人 / 岗位、处理说明 / 规则、输入、产出和关联资产；属性面板中的修改需点击“保存修改”。节点创建、连线、拖动、删除和整理布局会直接保存。
- **共享资产双向关联**：从步骤关联已有资产并跳转查看；在数据图的节点属性中查看引用它的流程。多个流程共享同一资产，每张图的步骤与排版独立。
- **流程撤销 / 重做**：每张流程独立保留当前会话内最多 100 步内容历史，切换流程可继续撤销；不回滚流程名称和说明。保存使用版本校验，其他页面的修改不会被旧页面覆盖，冲突后需重新打开流程。
- **流程导入 / 导出**：导出当前流程 JSON 或 PNG；从图目录导入流程 JSON 时创建新文档。JSON 保留步骤与资产 ID 引用，PNG 用于查看和分享。
- **原数据图三种视图**（同一张数据图的投影，不是三套数据）：
  - 系统视图：系统 / 数据库 / 接口 / 文件 / 外部方之间的数据流转
  - 业务视图：业务环节及其承载系统
  - 字段视图：表级血缘（连线含字段映射）
- **自动采集（自动为主，人工修）**：
  - **Excel 台账导入**：下载模板 → 填写 → 上传一键成图
  - **SQL 血缘解析**：粘贴/提交 SQL，基于 sqlglot 解析 INSERT-SELECT、CREATE TABLE AS、UPDATE 的表级与字段级血缘，支持 CTE、JOIN、UNION 和 mysql/postgresql/oracle/hive/spark 等方言；MERGE 当前提供表级血缘
  - **数据库只读采集**：直连 MySQL / PostgreSQL 读取库表元数据（只做 information_schema 级反射，不改数据）
- **人工修正**：画布拖拽建点、连线建流、属性面板编辑。人工改过的字段会记入保护名单，**重复采集不会覆盖**；仅在所有来源均确认对象消失后，才打「已消失」标记。
- **数据图撤销 / 重做**：手动创建、编辑、删除、布局均保存完整图的前后状态，撤销也写回数据库。切视图、选择和查询不进入编辑历史；导入、采集、恢复备份和加载演示数据实际改变图数据后才清空历史，失败或未应用的导入保留历史。检测到其他页面修改了数据时，旧撤销不会覆盖新数据。
- **血缘追溯**：右键任意节点「追溯上游 / 下游」，整图高亮链路（跨视图）。
- **数据图导出**：PNG 图片、JSON 备份/恢复。备份恢复完整校验节点、边及端点后一次提交；失败时保留原图。合并恢复包含已有节点的位置、边的标签和端点。
- **演示数据**：首次启动自动灌入一套订单业务场景，装好即可体验。
- **运行诊断**：`GET /api/health` 检查服务与数据库连接；关键操作输出阶段、数量、异常类型日志，不记录密码、SQL 或属性原文。新写入时间统一使用 UTC。

## 启动

需要 Python 3.10+ 和 Node.js 18+。

```bash
# 后端（端口 8000）
cd backend
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt      # Windows
# .venv/bin/pip install -r requirements.txt        # macOS/Linux
.venv/Scripts/python -m uvicorn app.main:app --port 8000

# 前端（端口 5173，另开一个终端）
cd frontend
pnpm install    # 或 npm install
pnpm dev
```

浏览器打开 [http://localhost:5173](http://localhost:5173)。前端通过 Vite 代理把 `/api` 转发到 8000 端口。

共享资产、原数据关系图和全部流程文档存在 `backend/data/dataflow.db`（SQLite）。现有数据库启动时会新增流程文档表，保留原有节点和边；删除数据库文件会同时清除这些内容。

## 备份范围

| 文件 | 包含的内容 | 导入入口 |
| --- | --- | --- |
| 原数据图 JSON 备份 | 原有节点、边、来源与布局，不包含任何流程文档 | 数据关系总图 → 恢复备份 |
| 流程 JSON（`process-diagram/v1`） | 当前一张流程的名称、说明、步骤、连线、排版与资产 ID 引用，不包含资产实体或其他流程 | 图目录 → 导入流程文件，创建新流程 |
| PNG | 图像，不包含可恢复的编辑数据 | 供查看和分享 |

流程 JSON 跨数据库导入时，所引用资产必须已在目标库存在、ID 一致且可用，否则导入失败。可先恢复原数据图备份，再导入相应流程。需要保留整个工作台时，停服务后复制 SQLite 数据库文件；两种 JSON 文件不能互相替代。

  app/services/

    db_introspect.py      # MySQL/PG 只读元数据采集
    graph.py              # 三视图过滤 + 血缘追溯

  tests/                  # pytest，含失败导入、恢复事务、来源隔离和字段血缘回归

  src/WorkspaceApp.tsx    # 图目录与工作台切换

## 已知边界（第一期）

- 流程功能当前为基础绘图与关系梳理，不包含流程执行引擎、实际任务派发、泳道或子流程。流程中的负责人和条件文字用于描述，不会自动触发审批或系统动作。
- 单张流程最多 500 个节点、2000 条连线；界面导入的流程 JSON 最大 10 MiB。允许保存未完成的草稿，结构校验不能替代业务规则审查。
- 撤销 / 重做历史保存在浏览器当前会话，页面刷新后不保留；已成功保存的图内容仍在数据库。删除整张流程不能通过内容撤销找回，可预先导出 JSON。
- 数据库采集只产出资产节点（库/表），表间流转关系来自 SQL 解析或 Excel 台账。
- SQL/Excel 的 `tbl:*` 是逻辑表；数据库采集的 `physical-tbl:*` 是物理表，按数据库类型、主机、端口、库名隔离，避免同名资产互相覆盖。物理表的 `attrs.logical_table` 记录逻辑表关联候选，当前不自动合并。
- 旧版已经采集的资产和来源记录会保留。重新采集生成明确的物理资产，不会自动删除或重命名旧节点。旧版多来源消失状态无法准确还原各来源是否有效，采用保守保留，后续由各来源的完整采集结果逐步确认。
- SQL/Excel 出现解析或行校验错误时只返回预览与错误，不写入图。数据库部分反射失败或达到采集限额时保留已有资产和读取失败的字段信息。
- 缺少表结构元数据时，`SELECT *` 只提供表级血缘并提示字段未知；歧义字段会报错，不猜测物理来源。PostgreSQL schema 的逻辑/物理资产关联仍需人工确认。
- 创建与备份恢复校验节点/边类型；人工 PATCH 不支持更改类型，提交 `type` 或未知字段返回 422。自动采集可修正未受人工保护的类型。
- MySQL / PostgreSQL 未传端口时分别使用 3306 / 5432；前端切换类型跟随默认端口并保留自定义端口。
- Excel 单文件最多 10 MiB，ZIP 解压总量最多 64 MiB、2048 个条目、100000 行；无效、超限文件不写入图。
- 当前编辑采用完整图 CAS 与完整快照撤销，适合小型本地图。数千节点会产生秒级提交耗时；规模测量与第二轮审查处理结果见 [第二轮修复记录](docs/review-round2.md)。
- 多人协作、定时采集、代码仓库扫描、全局搜索规划在第二期。
